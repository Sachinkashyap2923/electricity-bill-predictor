About the Electricity Bill Prediction System

Comprehensive overview of the system architecture, mathematical formulations, Machine Learning methodology, and defense preparation notes for MCA minor project viva.

1. Executive Summary & Abstract

Household and commercial electricity billing often presents unpredictability due to fluctuating weather, varying appliance loads, and billing cycle variations. This project implements a lightweight, explainable predictive web application using Python, Flask, Scikit-learn, SQLAlchemy, and SQLite.

Rather than treating billing as a pure black box, the system separates consumption forecasting (units in kWh) from tariff computation (energy charges, fixed meter fees, and percentage duties). This structure guarantees transparency, allows users to configure their local tariffs, and provides clear auditability.

2. Mathematical Formulation & Billing Logic

The billing engine follows a multi-tiered formula:

1. Energy Charge = Predicted Monthly Consumption (kWh) × Tariff Rate per kWh
2. Additional Charges = Energy Charge × (Additional Charge Percentage / 100)
3. Estimated Total Bill = Energy Charge + Fixed Charges + Additional Charges

Calculations utilize decimal.Decimal with half-up rounding to prevent floating-point accumulation errors.

3. Machine Learning Methodology

Model 1: Linear Regression

Computes an optimal hyper-plane by minimizing the Ordinary Least Squares (OLS) residual sum of squares: y = β₀ + β₁(Daily Usage) + β₂(Previous Month) + β₃(Billing Days) + ε. It offers high interpretability and low computational overhead.

Model 2: Random Forest Regressor

An ensemble of 100 decorrelated decision trees using bootstrap aggregating (bagging) and feature subsampling. It captures non-linear appliance efficiency thresholds and interaction surges.

Data Leakage Prevention:

Standardization (StandardScaler) is fit strictly on the 80% training partition. The test partition (20%, 300 samples) remains completely unseen during scaling and model fitting.

4. MCA Viva Frequently Asked Questions (FAQ)

Q1: Why predict electricity consumption (kWh) first instead of the bill amount directly?

Ans: Utility tariffs vary across regions, seasons, and customer categories. By predicting physical consumption (kWh) with Machine Learning, the model learns human usage dynamics that remain valid regardless of tariff changes. The financial bill is then calculated via configurable tariff rules.

Q2: Why did one model perform better than the other?

Ans: Consumption is predominantly linear with respect to daily consumption and billing days. Linear Regression achieves lower variance with fewer degrees of freedom, whereas Random Forest may introduce slight step-function discretization error unless deep trees are used.

Q3: How does the application prevent out-of-distribution extrapolation?

Ans: During training, the pipeline records the minimum, maximum, mean, and standard deviation of each feature in metrics.json. When a user submits values outside these bounds, the system displays an explicit extrapolation warning notice.

Real Dataset Replacement

To transition from the synthetic demonstration dataset to real utility records:

  1. Export smart-meter CSV records with columns matching average_daily_consumption_kwh, previous_month_consumption_kwh, billing_days, and monthly_consumption_kwh.
  2. Place file at datasets/electricity_consumption.csv.
  3. Run python -m app.ml.train_models.
